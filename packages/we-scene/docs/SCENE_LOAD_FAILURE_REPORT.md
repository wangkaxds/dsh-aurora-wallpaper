# 三个"加载不出来"的场景分析报告

分析对象（workshop\content\431960）：

| 场景 | 文件夹 | pkg 大小 |
|---|---|---|
| 战双帕弥什·露西亚·誓焰 | 3416436251 | 36.4 MB |
| Reze \| Chainsaw Man | 3624053922 | 20.8 MB |
| 空之境界·无垢·两仪式 | 3667944887 | 28.9 MB |

## 一、逐场景结论

### 1. 露西亚（3416436251）—— 主视觉是视频纹理层
scene.json 仅 3 个对象：

1. `models/RecorderClip_001.json` → 材质纹理 `materials/RecorderClip_001.tex` 为 **视频纹理**（WE 录屏视频层，占满 3840×2160）
2. 粒子对象：`particles/presets/leaves5.json`（樱花）
3. 声音对象（mp3）

**根因：场景的主视觉完全由视频纹理层构成，渲染器不支持视频纹理（加载时直接丢弃）。** 粒子也不支持。所以渲染出来只剩空背景 —— 表现为"加载不出来"。

### 2. Reze | Chainsaw Man（3624053922）—— 同上是视频纹理层
scene.json 仅 3 个对象：

1. `models/Reze.json` → 材质纹理 `materials/Reze.tex` 为 **视频纹理**（2560×1440 主视觉）
2. 粒子对象：`particles/workshop/2446178284/rising_debris_copy1.json`（上升碎屑）
3. 声音对象（mp3）

**根因：与露西亚完全相同 —— 主视觉是视频纹理层。**

### 3. 空之境界·两仪式（3667944887）—— 效果 shader 转译 bug（已修复）
63 个对象：51 个 image 层 + 5 个粒子 + 2 个文字对象 + 5 个其他。

纹理格式 R8 / DXT5 / ARGB8888 均受支持。但效果 shader 中 `effects/iris` 有两个转译缺陷，导致渲染在第一帧抛错、整个场景渲染不出来：

1. `1 - g_Rough`（整数字面量减 float uniform）→ GLSL 无隐式转换，编译失败
2. `smoothstep(..., 1, ...)`（float 函数实参为裸 int）→ 无匹配重载，编译失败

**状态：两个转译缺陷已修复，该场景现已能渲染**（无头验证：0 错误）。此场景的粒子/文字对象仍不显示，但不影响主视觉。

## 二、三个场景共同暴露的能力缺口（按优先级）

| 缺口 | 影响场景 | 说明 |
|---|---|---|
| **视频纹理层**（P0） | 露西亚、Reze\|CSM | 两个场景主视觉全靠它；WE 用 mp4 纹理做层输入，需解码视频帧上传 WebGL |
| 粒子系统（P1） | 全部三个 | 樱花/碎屑/灰烬/光斑；WE 粒子有完整生命周期系统 |
| 文字对象（P2） | 空之境界 | scene.json 里的 text 对象（时钟、歌词等） |
| 声音对象（P2） | 全部三个 | mp3 循环播放（浏览器 HTMLAudio 即可） |
| lightshafts 效果验证（P1） | 空之境界 | 转译已通过，需实际渲染验证 GLSL 编译与画面 |

## 三、与"组件"的关系

这三个场景都不含 components（组件）。它们加载不出来的原因与组件无关，而是视频纹理 / 粒子 / 文字 / 效果 shader 的能力缺口。

组件（时钟、天气、音频可视化等）是另一条独立工作线，目前完全不支持渲染与参数设置。

## 四、建议路线

1. P0：视频纹理层支持（一次实现，露西亚、Reze|CSM 两个场景直接复活）
2. P1：粒子系统 + lightshafts 渲染验证（空之境界完整化）
3. P2：文字对象 + 声音
4. P3：组件渲染与参数面板
